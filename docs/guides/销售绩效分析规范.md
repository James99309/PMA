# 销售绩效分析规范

## 分析层次（由表及里）

```
第一层：KPI 完成率（看结果）
  ↓ 完成率低时追问"为什么"
第二层：项目管线质量（看过程）
  ↓ 管线有问题时追问"根因在哪"
第三层：客户角色均衡性（看方向）
  ↓ 方向偏差时追问"谁在管"
第四层：管理有效性（看管理）
  ↓ 最终形成
第五层：下一阶段预期（看未来）
```

---

## 一、KPI 硬指标——"做了多少"

| 指标 | 定义 | 数据来源 | 判断要点 |
|------|------|---------|---------|
| 批价完成率 | 已审批批价单金额 / 季度目标 | pricing_orders (approved) | 按绩效系数表直接评定 |
| 商机面价 | 商机关联的报价单金额，指向植入 | quotation_details → 关联项目的面价汇总 | 是植入方向的指标，不等于批价 |
| 集成商签约 | 已签约的集成商/代理商数量 | companies (dealer/integrator) | 签约数量 + **是否有项目关联** |
| 新客户数 | 新录入客户数量 | companies (owner_id) | 数量 + 角色分布是否健康 |
| 项目存活率 | 活跃项目 / 总项目 | projects (is_active) | 100% 存活可能意味着未清理死项目 |

### 关键说明

- **商机面价**：不是报价单本身的金额，而是报价单所关联商机（项目）的面价汇总，代表植入方向的规模
- **集成商签约**：不仅看签约数量，还要聚合该集成商关联的项目、行动记录，判断签约是否转化为实际业务推进
- **所有指标都需要聚合销售的全部记录**（actions、work_items、worklogs、change_logs）来综合分析，不能孤立看单一数据表

---

## 二、项目管线质量——"做到什么程度"

### 阶段分布健康度

```
健康漏斗:              不健康漏斗（头重脚轻）:
discover  ████████     discover  ████████████████
embed     ██████       embed     ████
design    ████         design
bid       ███          bid
won       ██           won
```

| 检查项 | 健康标准 | 危险信号 |
|--------|---------|---------|
| 阶段分布 | 各阶段均有项目 | 70%+ 停在 discover |
| 推进速度 | 30 天内应推进到下一阶段 | 建立超 30 天仍在 discover |
| 有效项目比例 | 空壳（无跟进记录）应 < 20% | 大量无跟进的空壳项目 |
| 关联完整度 | 角色字段（end_user/dealer/integrator/contractor）已填 | 角色字段全空 |

### 阶段说明

- **rejected 不纳入阶段评估**——rejected 是审批流程的状态，不是项目阶段，不影响管线分析
- 管线分析仅关注：discover → embed → design → bid → won → delivery 的推进情况

## 三、客户角色均衡性——"方向对不对"

### 健康比例基准

| 客户角色 | 健康占比 | 说明 |
|----------|---------|------|
| 设计院 (designer) | **10%** | 信息源头，少而精 |
| 集成商 (integrator) | **20%** | 项目执行推手 |
| 终端用户 (user) | **30%** | 最终买单方 |
| 代理商 (dealer) | **40%** | 渠道覆盖和复制 |

### 均衡性检查方法

需要从**两个维度**同时检查：

**维度一：客户库角色分布**
- 统计 companies 表中 company_type 的分布比例
- 与健康比例基准对比，识别偏差方向

**维度二：行动记录角色分布**
- 统计 actions 和 work_items 关联客户的 company_type 分布
- **行动记录的角色分布也应呈现 10%/20%/30%/40% 的健康比例**
- 如果客户库比例合理但行动集中在某一类角色，说明精力分配失衡

### 均衡性判断标准

| 偏差类型 | 特征 | 后果 |
|----------|------|------|
| 设计院过重（>20%） | 大量设计院拜访，项目来源集中在"画图纸" | 信息多但成交周期长，embed 后推不动 |
| 代理商不足（<30%） | 缺乏渠道合作伙伴 | 无法实现区域覆盖和业务复制 |
| 终端用户不足（<20%） | 不接触最终决策人 | 对需求理解浮于表面，报价缺乏针对性 |
| 集成商不足（<15%） | 项目有信息无执行 | embed 阶段的项目无法向 design/bid 推进 |

### 不纳入均衡性分析的维度

- **地域分布**：不作为均衡性指标（不同区域销售有不同的地域侧重）
- **行业分布**：不作为均衡性指标（不同行业有不同的项目周期特征）

### 未录入客户/角色识别（每次评估必做）

从行动记录（actions.communication + work_items.title + worklogs.additional_notes）中提取已接触但未录入系统的客户：
- 重点识别终端用户（业主/甲方/采购/运维）和设计院——系统中为 0 但日志中有拜访记录的角色
- 检查是否已在系统中归属其他人——其他人超过 3 个月无跟进 → 建议协调归属
- **输出"立即录入清单"**

### 业务影响力预判（每个关键项目必须分析）

从每个已中标/投标中项目的行动时间线中，分析行动链条的角色组成：

| 影响力 | 行动链条特征 | 含义 |
|--------|-----------|------|
| ✅ 有把握 | 有终端用户互动记录 | 能直接影响业主决策 |
| ⚠️ 被动 | 仅集成商和代理商互动 | 成败取决于集成商态度 |
| ❌ 无影响力 | 无行动或仅内部会议 | 完全被动等待 |

关键判断：代理商的日常活动和终端用户之间是否有关联？如果代理商行动全部面向集成商而不是终端用户，业务就没有足够的影响力来把握成败，完全由集成商决定。

## 四、管理有效性——"谁在负责方向"

### 上级行动记录分析

通过聚合上级在该销售项目/客户上的 actions 和 work_items 记录，评估：

| 检查项 | 正面信号 | 负面信号 |
|--------|---------|---------|
| **方向一致性** | 上级带队拜访的客户角色分布与健康比例一致 | 上级拜访集中在某一类角色（如全是设计院），加重销售的偏差 |
| **修偏能力** | 发现销售角色失衡后引导其调整方向 | 放任或未察觉销售的角色失衡 |
| **项目推进督导** | 停滞项目有上级介入的复盘/推动记录 | 空壳项目和停滞项目长期未被发现 |
| **业务节奏引导** | 季末从散点拜访收敛为聚焦攻关 | 全季保持相同节奏，无收敛 |
| **报价→批价推动** | 报价后有明确的议价/签约跟进行动 | 报价发出后无下文 |

### 上级行动角色分布检查

上级带队或参与的行动记录，同样应检查其客户角色分布：
- 如果上级的行动也集中在设计院端 → 方向引导本身有问题
- 如果上级的行动补充了集成商/代理商端 → 有修偏意识

## 五、下一阶段批价预判——"接下来会怎样"

### 5.1 建立批价率基准

查询该销售历史批价单，按**项目维度**计算：
```
批价率 = 批价金额(pricing_total_amount) / 同项目报价单面价(Σ quotation_details.market_price × quantity)
```
- 报价面价从批价单关联的**同一项目**的报价单获取（通过 project_id），不是批价单自身字段
- 典型批价率区间 37%-45%

### 5.2 逐项目预估（仅已中标+投标中且有行动的项目）

| 阶段 | Q内有行动 | 概率级别 | 预估方式 |
|------|---------|---------|---------|
| **已中标 + 密集行动** | ✅ | **大概率** | 报价面价 × 批价率基准 |
| **已中标 + 少量行动** | ✅ | **中概率** | 同上，需确认状态 |
| **投标中 + 有行动** | ✅ | **一定可能** | 需先中标，金额预估打折 |
| 已中标但无行动 | ❌ | 需确认 | 可能已丢失/搁置 |

### 5.3 Q2 批价预期汇总（三场景）

```
保守 = 仅已中标且高行动量项目 × 批价率
中等 = 保守 + 已中标中等行动项目
乐观 = 中等 + 部分投标中标项目
```

### 5.4 销售需确认问题清单（每次评估必须输出）

| 确认类别 | 具体问题 |
|---------|---------|
| **报价单匹配** | 每个候选项目的报价单是否反映最新方案？方案变更后是否更新报价？ |
| **项目状态** | Q内无跟进的已中标/投标中项目是否仍活跃？投标结果是否已出？ |
| **商务瓶颈** | 最高行动量项目卡在哪里？价格/品牌/合同条款？ |
| **加强把握** | 哪些项目可通过增加终端用户互动提高成功率？ |

### 5.5 同期历史对比（与自身比，不与他人比）

- 上一年同季度的批价/报价数据
- 报价→批价转化率变化
- 行动力指标同比

## 六、代理商深度分析（区域销售重点）

### 代理商 vs 合作伙伴比例
- partner 纳入 dealer 统计
- 合作伙伴占比 >60% = 代理商发展不良，需推动签约转化

### 行动集中度
- 单家代理商占行动 >30% = 过度依赖
- Q内行动为 0 的代理商/合作伙伴比例——沉默渠道需激活或淘汰

### 代理商行动对象（最关键）
- 检查代理商行动是面向**集成商**还是**终端用户**
- 全部面向集成商 = 代理商在扮演"二号集成商"，未起到连接终端用户的桥梁作用
- **代理商项目中不能只有集成商互动而没有终端用户交互，否则项目决策完全被动**

### 区域覆盖
- 每个重点区域应有至少 1 家活跃代理商

### Q2 代理商行动要求
- 完成潜在代理商签约，激活沉默代理商
- 每家代理商每季度至少 2 次终端用户拜访
- 代理商和项目的区域分布均衡
- 要求和代理商接触有项目的最终客户行动增加

## 七、行动分布分析

### 行动的阶段分布
- 统计 actions/work_items 按关联项目的 current_stage 分组
- 行动应集中在已中标和投标中阶段（最接近成交）
- 发现/植入阶段行动过多而已中标/投标中过少 = 精力分配错误

### 行动集中度
- 单项目占行动 >30% 需关注（是否合理取决于项目阶段和金额）
- 已中标/投标中项目 >30 天无行动 = 可能丢单风险

### 阶段推进活跃度
- 检查 change_logs 中 current_stage 字段变更记录
- Q内零阶段推进 = 管线停滞或系统数据未更新（两者都是问题）

## 评估公式

```
综合评级 = KPI完成率(20%) + 管线质量(20%) + 客户角色均衡(20%) + 行动力(25%) + 数据质量(15%)
```

| 等级 | 分数区间 | 含义 |
|------|---------|------|
| A | 3.5+ | KPI 达标，管线健康，角色均衡 |
| B | 2.8-3.4 | KPI 接近达标或行动力强但结构有偏 |
| C | 2.0-2.7 | KPI 未达标，管线或结构有明显问题 |
| D | <2.0 | 多维度不合格 |

---

## 分析口诀

```
一看批价有没有，
二看管线通不通，
三看角色均不均，
四看上级管没管，
五看下季能不能。
```

## 数据聚合要求

每次分析必须聚合以下数据源：

| 数据源 | 用途 |
|--------|------|
| `pricing_orders` | 批价完成率 |
| `quotations` + `quotation_details` | 商机面价（关联项目） |
| `projects` | 管线阶段分布、推进速度 |
| `companies` | 客户角色分布 |
| `contacts` | 客户数据完整度 |
| `actions` | 行动记录角色分布、上级协同分析 |
| `work_items` + `worklogs` | 行动力、行动角色分布、日志质量 |
| `change_logs` | 系统活跃度、数据维护 |

**所有角色分析（客户分布 + 行动分布 + 上级行动分布）必须同时呈现，交叉验证。**

---

## 对比规则

**禁止与其他销售人员对比。** 每个销售的区域、行业、入职时间、客户基础不同，横向对比无意义。

**只做两种自身对比**：
1. **同期往年对比**：去年同季度数据（批价/报价/行动/转化率）
2. **上一季度对比**：本年上一季度数据
