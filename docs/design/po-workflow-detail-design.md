## 一、采购订单完整流程

### 1.1 流程概览

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│  审批   │ → │供应商确认│ → │工厂测试 │ → │  FAT   │ → │  发货   │ → │验收入库 │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
     ↑              ↑             ↑            ↑             ↑            ↑
  标准审批      签名+回执      技术测试     技术测试      物流信息     数量核对
  (内部)       (供应商)      (供应商)    (地点二选一)   (供应商)     (内部)
```

### 1.2 FAT测试地点选择

**创建订单时选择，选择后流程固定**：

| 选项 | 名称 | 执行地点 | 执行时机 | 流程顺序 |
|------|------|----------|----------|----------|
| `site_fat` | 现场FAT | 供应商工厂 | 发货前 | 审批→确认→工厂测试→**FAT**→发货→验收 |
| `incoming` | 到货测试 | 我方仓库 | 到货后 | 审批→确认→工厂测试→发货→**到货测试**→验收 |

### 1.3 各步骤详细说明

| 步骤 | 执行者 | 动作类型 | 输出 | 前置条件 |
|------|--------|----------|------|----------|
| 审批 | 供应链负责人 | authorization | 审批意见 | 订单已创建 |
| 供应商确认 | 供应商账号 | form_confirm | 签名+回执文件 | 审批通过 |
| 工厂测试 | 供应商/外部链接 | form_confirm | 测试报告+签名 | 供应商已确认 |
| FAT测试 | 我方人员/外部链接 | form_confirm | 测试报告+签名 | 工厂测试通过 |
| 发货 | 供应商账号 | form_confirm | 物流信息 | FAT通过(site_fat) 或 工厂测试通过(incoming) |
| 到货测试 | 我方人员 | form_confirm | 测试报告+签名 | 已到货(仅incoming模式) |
| 验收入库 | 我方人员 | form_confirm | 验收单 | 所有测试通过+已到货 |

## 二、测试流程设计

### 2.1 测试模式

创建测试任务时选择：

| 模式 | 说明 | 测试数量 | 报告上传 | 签名 |
|------|------|----------|----------|------|
| **全部测试** | 对所有设备逐一测试 | 全部N台 | 每台1份 | 最后1次 |
| **采样测试** | 随机抽取部分测试 | 抽取M台 | 每台1份 | 最后1次 |

### 2.2 采样测试规则

- 用户输入采样数量（如：10台中抽4台）
- 系统从已录入的序列号中**随机抽取**
- **抽取后不可更改**（确保测试公正性）
- 抽取的序列号在测试表单中固定显示

## 四、序列号规范

### 4.1 生成时机

| 事件 | 动作 |
|------|------|
| 审批通过 | 系统自动生成序列号（状态：registered） |
| 供应商确认 | 序列号锁定，不可修改 |
| 验收入库 | 序列号状态更新为 in_stock |

### 4.2 编码格式

```
{供应商编码}-{产品编码}-{批次号}-{序号}
    3-4位        5位       5位     4位

示例：EVT-RF31P-2501A-0001
```

### 4.3 各段说明

| 段 | 长度 | 规则 | 示例 |
|---|------|------|------|
| 供应商编码 | 3-4位 | 大写字母，管理员分配 | EVT, HW, ZTE |
| 产品编码 | 5位 | 大写字母+数字，创建产品时设置 | RF31P, EFH20 |
| 批次号 | 5位 | YYMM + 批次字母 | 2501A = 2025年1月第1批 |
| 序号 | 4位 | 批次内顺序，0001-9999 | 0001, 0023 |

### 4.4 唯一性保障

1. **数据库约束**：`serial_number` 字段 `unique=True`
2. **序号表**：`SerialNumberSequence` 表记录每个前缀的最后序号，使用行级锁防止并发冲突
3. **生成时校验**：生成后再次检查唯一性

## 六、用户账号与公司关联

### 6.1 现有问题

- `User.company_name` 是文本字段，存"我方公司名称"
- `Company` 表存客户/供应商
- 代理商账号与 Company 表无关联

### 6.2 解决方案

**新增字段**：`User.linked_company_id`

```python
class User(db.Model):
    # 现有字段
    company_name = db.Column(db.String(100))  # 我方公司名称（内部用户）

    # 新增字段
    linked_company_id = db.Column(db.Integer, db.ForeignKey('companies.id'), nullable=True)
    linked_company = db.relationship('Company', backref='users')
```

### 6.3 用户类型判断

| 用户类型 | company_name | linked_company_id |
|----------|--------------|-------------------|
| 内部员工 | "我方公司" | NULL |
| 供应商账号 | NULL | 供应商Company.id |
| 代理商账号 | NULL | 代理商Company.id |
| 客户账号 | NULL | 客户Company.id |

### 6.4 数据迁移

需要迁移现有代理商账号：
```python
# 通过公司名称匹配关联
for user in external_users:
    company = Company.query.filter_by(company_name=user.company_name).first()
    if company:
        user.linked_company_id = company.id
```

## 七、审批动作扩展

### 7.1 动作类型

| action_type | 说明 | 使用场景 |
|-------------|------|----------|
| `authorization` | 标准审批 | 内部审批（通过/驳回） |
| `form_confirm` | 表单确认 | 供应商确认、测试、发货、验收等 |

### 7.2 form_confirm 动作参数

```python
action_params = {
    "form_id": "factory_test_form",  # 表单模板ID
    "access_mode": "external",        # internal/external
}
```

### 7.3 访问模式

| access_mode | 说明 | 认证方式 |
|-------------|------|----------|
| `internal` | 内部访问 | 需登录（供应商主账号或内部员工） |
| `external` | 外部链接 | Token访问（临时人员，如工厂测试员） |

### 7.4 外部访问Token

```python
class ApprovalExternalToken(db.Model):
    """审批外部访问令牌"""
    id = Column(Integer, primary_key=True)
    token = Column(String(64), unique=True)      # 访问令牌
    step_id = Column(Integer, ForeignKey('approval_steps.id'))
    object_type = Column(String(50))             # purchase_order
    object_id = Column(Integer)
    expires_at = Column(DateTime)                # 过期时间
    used_at = Column(DateTime)                   # 使用时间
    created_at = Column(DateTime, default=func.now())
```
