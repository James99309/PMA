## 背景和需求

### 业务痛点

**当前问题**：
1. ❌ 产品库无规格系统，销售选择产品困难
2. ❌ 同一产品系列有多个规格变体（如直放站有不同频率、功率组合）
3. ❌ 销售报价时容易选错产品MN号
4. ❌ 批价单中看不到产品的具体配置组合
5. ❌ 附加产品（模块、配件）需要手动选择，容易遗漏

**业务需求**：
1. ✅ 通过规格筛选快速找到正确的产品
2. ✅ 支持产品+附加产品的组合配置
3. ✅ 报价单和批价单中清晰显示产品配置明细
4. ✅ 兼容现有产品库和研发库的数据

### 典型场景

**场景1：直放站产品选择**
```
业务需求：客户需要900MHz频率、50W功率的直放站，带馈电模块220V

当前问题：
- 销售需要记住MN号或在产品列表中逐个查找
- 容易选错频率或功率型号
- 馈电模块需要单独添加，容易遗漏

期望体验：
- 选择"ZFZ系列直放站"
- 选择频率：900MHz
- 选择功率：50W
- 系统自动找到：ZFZ-900-50W
- 提示选择馈电模块：220V
- 一键添加到报价单
```

**场景2：批价单确认**
```
当前问题：
- 批价单只显示MN号，看不到规格组合
- 批价工需要查阅产品库确认规格

期望体验：
- 批价单显示：直放站900MHz 50W (MN: ZFZ-900-50W)
- 规格明细：频率900MHz | 功率50W | 驻波比≤1.5
- 附加产品：馈电模块220V
```

## 核心设计原则

### 1. 统一的规格筛选逻辑 ✅

**核心原则**：所有产品使用相同的规格匹配逻辑

```
规格只用于匹配查询，不用于生成MN号

选择规格 → 查询符合规格的产品 → 返回产品列表（包含MN号）
```

**适用范围**：
- ✅ 新产品（从研发库转化，MN号可能是编码拼接）
- ✅ 老产品（手动添加，MN号是任意格式）
- ✅ 未来产品（任意MN号格式）

**不区分产品类型**：
- ❌ 不需要 `product_type` 字段区分产品类型
- ❌ 不需要 `spec_code` 字段用于MN号编码
- ❌ 不需要编码拼接逻辑
- ✅ 只需要规格名称和规格值进行匹配查询

---

### 5. 待定状态支持 ✅

**核心**：支持规格"不确定"状态，延后确定具体配置

**业务场景**：
- 销售初期报价时，客户尚未确定具体规格（如频率、功率）
- 先提供默认配置的价格，待客户确认后再更新具体规格

**待定状态逻辑**：

```
规格选择界面：
  频率：
  ○ 800MHz  ○ 900MHz  ○ 1800MHz  ● 不确定

附加产品选择界面：
  馈电模块：
  ○ 220V  ○ 110V  ● 不需要
```

**"不确定"与"不需要"的区别**：

| 类型 | 使用场景 | 默认行为 | 显示效果 | 警告提示 |
|-----|---------|---------|---------|---------|
| **不确定** | 必选规格（如频率、功率） | 自动选择第一个选项值 | 规格显示"待定" | ⚠️ 红色警告 |
| **不需要** | 附加产品/功能 | 不添加该产品 | 不显示该附加产品 | 无警告 |

**报价单显示**：

```
序号 | MN号          | 产品名称          | 规格                  | 数量 | 单价   | 小计
-----|--------------|-------------------|----------------------|------|--------|-------
1    | DC-Z-08-50   | 直放站800MHz 50W  | 频率:待定 ⚠️          | 1    | ¥5,500 | ¥5,500
     |              |                   | 功率:50W              |      |        |
```

**实现机制**：
1. ✅ **默认MN选择**：选择"不确定"时,系统使用第一个规格选项值查询产品
2. ✅ **标记待定状态**：在quotation_items表中标记哪些规格是"待定"状态
3. ✅ **视觉警告**：报价单和批价单中对"待定"规格显示红色警告图标
4. ✅ **后期确认**：销售可以在客户确认后编辑报价单,更新为实际规格
5. ✅ **价格更新**：规格确认后,如果新规格的产品价格不同,自动更新报价单价格

**数据存储**：
- `quotation_items.pending_specs` (JSON字段): 存储待定规格列表
  ```json
  {
    "pending_specs": ["频率", "电压"],
    "default_specs": {
      "频率": "800MHz",  // 用于计算价格的默认值
      "电压": "220V"
    }
  }
  ```

---

### 2. 规格在分类中定义 ✅

**原则**：规格模板在产品分类/子类中预定义

**原因**：
- 同一分类的产品，规格类型是统一的
- 预定义规格可选值，确保数据一致性
- 添加产品时自动加载规格模板
- 便于维护和管理

**示例**：
```
产品分类：直放站 > ZFZ系列
规格模板：
  - 频率 (下拉选择: 800MHz, 900MHz, 1800MHz)
  - 功率 (下拉选择: 50W, 100W)
  - 驻波比 (文本输入)
  - 增益 (数值输入)
```

---

### 3. 统一研发库和产品库 ✅

**分类体系统一**：
- `product_categories` - 产品大类（研发库和产品库共用）
- `product_subcategories` - 产品子类（研发库和产品库共用）
- `product_regions` - 产品地区（研发库和产品库共用）

**规格体系统一**：
- 研发库：`dev_product_specs`
- 产品库：`product_specs` (新增，结构相同)
- 字段统一：`spec_name`, `spec_value`

**数据流转**：
```
研发库 (dev_products + dev_product_specs)
    ↓ 产品化
产品库 (products + product_specs)
    ↓ 配置选择
报价单 (quotations + quotation_items)
```

---

### 4. 产品组合模式 ✅

**核心**：配置结果 = 主产品 + N个附加产品（依赖关系）

```
用户配置：
  1. 选择主产品（通过规格筛选）
  2. 选择附加产品（馈电模块、电源适配器等）

报价单结果：
  序号 | MN号                | 产品名称          | 数量 | 单价   | 小计
  -----|--------------------|--------------------|------|--------|-------
  1    | ZFZ-900-50W        | 直放站900MHz 50W   | 1    | ¥6,500 | ¥6,500
  2    | ↳ MODULE-FEED-220V | 馈电模块220V       | 1    | -      | -
```

**附加产品特殊逻辑**：
- ✅ **独立行显示**：附加产品在报价单中形成独立行，使用 `↳` 符号标识依赖关系
- ✅ **数量联动**：附加产品数量自动随主产品数量调整，不可单独编辑
- ✅ **价格合并**：附加产品不显示单独价格，价格合并到主产品中
- ✅ **不可编辑**：附加产品行在报价单中为只读状态，只能通过主产品配置修改
- ✅ **批价单BOM**：批价单可以看到完整的产品组合清单

**优势**：
- ✅ 每个产品保持独立的MN号（便于生产和库存管理）
- ✅ 批价单可以看到完整的BOM清单
- ✅ 库存管理独立跟踪每个产品
- ✅ 报价单中清晰展示产品依赖关系

## 数据库结构设计

### 核心表结构

#### 1. 产品表（products）- 扩展

```sql
-- 扩展现有 products 表
ALTER TABLE products
ADD COLUMN category_id INTEGER,           -- 产品大类（关联 product_categories）
ADD COLUMN subcategory_id INTEGER,        -- 产品子类/系列（关联 product_subcategories）
ADD COLUMN region_id INTEGER,             -- 产品地区（关联 product_regions）
ADD COLUMN source_type VARCHAR(20),       -- 来源类型: dev_product, manual, import
ADD COLUMN source_dev_product_id INTEGER, -- 源研发产品ID（可选）
ADD COLUMN productized_at DATETIME;       -- 产品化时间（可选）

-- 添加外键约束
ALTER TABLE products
ADD CONSTRAINT fk_products_category
  FOREIGN KEY (category_id) REFERENCES product_categories(id),
ADD CONSTRAINT fk_products_subcategory
  FOREIGN KEY (subcategory_id) REFERENCES product_subcategories(id),
ADD CONSTRAINT fk_products_region
  FOREIGN KEY (region_id) REFERENCES product_regions(id),
ADD CONSTRAINT fk_products_source_dev
  FOREIGN KEY (source_dev_product_id) REFERENCES dev_products(id);

-- 添加索引
CREATE INDEX idx_products_category ON products(category_id);
CREATE INDEX idx_products_subcategory ON products(subcategory_id);
```

**字段说明**：

| 字段 | 类型 | 说明 | 示例 |
|-----|------|------|------|
| category_id | INTEGER | 产品大类ID | 1 (直放站) |
| subcategory_id | INTEGER | 产品子类/系列ID | 2 (ZFZ系列) |
| region_id | INTEGER | 产品地区ID | 1 (中国) |
| source_type | VARCHAR(20) | 来源类型 | dev_product / manual / import |
| source_dev_product_id | INTEGER | 源研发产品ID | 123 |
| productized_at | DATETIME | 产品化时间 | 2025-10-26 14:30 |

**说明**：
- `subcategory_id` 同时代表产品子类和产品系列，复用现有 `product_subcategories` 表
- 产品图片通过现有的 `image_path` 字段存储，无需新增字段

#### 1.5 报价单明细表（quotation_items）- 扩展

```sql
-- 扩展现有 quotation_items 表（支持待定状态和附加产品依赖）
ALTER TABLE quotation_items
ADD COLUMN pending_specs JSON,           -- 待定规格信息
```

**新增字段说明**：

| 字段 | 类型 | 说明 | 示例 |
|-----|------|------|------|

**pending_specs JSON结构**：
```json
{
  "pending_specs": ["频率", "电压"],        // 标记为"待定"的规格名称列表
  "default_specs": {                       // 用于计算价格的默认规格值
    "频率": "800MHz",
    "电压": "220V"
  }
}
```

#### 2. 产品规格表（product_specs）- 新增

```sql
-- 创建产品规格表（结构与 dev_product_specs 完全一致）
CREATE TABLE product_specs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    product_id INTEGER NOT NULL,
    field_name VARCHAR(100) NOT NULL,     -- 规格名称（如"频率"）
    field_value VARCHAR(255) NOT NULL,    -- 规格值（如"800MHz"）
    field_code VARCHAR(10),                -- 规格编码（对应 product_code_field_options.code）
    display_order INTEGER DEFAULT 0,      -- 显示顺序
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE
);

-- 添加索引（重要：用于规格筛选查询）
CREATE INDEX idx_product_specs_product ON product_specs(product_id);
CREATE INDEX idx_product_specs_field_name ON product_specs(field_name);
CREATE INDEX idx_product_specs_field_value ON product_specs(field_value);
CREATE INDEX idx_product_specs_name_value ON product_specs(field_name, field_value);
```

**字段说明**：
- `field_name` / `field_value` - 与 `dev_product_specs` 字段名保持一致
- `field_code` - 规格编码，对应 `product_code_field_options.code`，用于MN号生成
- 规格定义来自 `product_code_fields` 表（复用现有规格定义体系）

**示例数据**：
```sql
-- 产品1：DC-Z-08-50
INSERT INTO product_specs (product_id, field_name, field_value, field_code, display_order) VALUES
(1, '频率', '800MHz', '08', 1),
(1, '功率', '50W', '50', 2),
(1, '驻波比', '≤1.5', NULL, 3);

-- 产品2：MODULE-FEED-220V
INSERT INTO product_specs (product_id, field_name, field_value, field_code, display_order) VALUES
(2, '电压', '220V', '22', 1),
(2, '功率', '100W', '10', 2);
```

#### 3. 产品关联表（product_relations）- 新增

```sql
-- 创建产品关联表（定义主产品与附加产品的关系）
CREATE TABLE product_relations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    main_product_type VARCHAR(20) NOT NULL,   -- 'subcategory' 或 'product'
    main_product_id INTEGER NOT NULL,         -- 子类ID或产品ID
    related_product_id INTEGER NOT NULL,      -- 关联产品ID
    relation_type VARCHAR(50) NOT NULL,       -- 关联类型
    display_name VARCHAR(100),                -- 显示名称
    default_quantity INTEGER DEFAULT 1,       -- 默认数量
    is_required BOOLEAN DEFAULT FALSE,        -- 是否必选
    display_order INTEGER DEFAULT 0,          -- 显示顺序
    is_active BOOLEAN DEFAULT TRUE,           -- 是否启用
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (related_product_id) REFERENCES products(id) ON DELETE CASCADE
);

CREATE INDEX idx_product_relations_main ON product_relations(main_product_type, main_product_id);
CREATE INDEX idx_product_relations_related ON product_relations(related_product_id);
```

**关联类型**（relation_type）：
- `optional_accessory` - 可选配件
- `required_accessory` - 必需配件
- `recommended` - 推荐产品

**示例数据**：
```sql
-- ZFZ系列（subcategory_id=2）的关联产品
INSERT INTO product_relations (main_product_type, main_product_id, related_product_id, relation_type, display_name, is_required) VALUES
('subcategory', 2, 201, 'optional_accessory', '馈电模块（220V）', FALSE),
('subcategory', 2, 202, 'optional_accessory', '馈电模块（110V）', FALSE),
('subcategory', 2, 203, 'optional_accessory', '电源适配器（110V）', FALSE);

-- 也可以为具体产品配置专属附加产品
INSERT INTO product_relations (main_product_type, main_product_id, related_product_id, relation_type, display_name, is_required) VALUES
('product', 1, 204, 'required_accessory', '专用电池组', TRUE);
```

**说明**：
- `main_product_type = 'subcategory'` - 为整个子类/系列配置通用附加产品
- `main_product_type = 'product'` - 为具体产品配置专属附加产品
- 复用 `product_subcategories` 表作为系列定义，无需创建新的 `product_series` 表

## 业务流程设计

### 流程1：规格模板配置（管理员）⭐ 复用现有系统

#### 步骤1：在产品子类中定义规格字段

**操作入口**：产品管理 > 产品分类管理 > 选择子类 > 编码字段管理

**操作流程**：
1. 选择产品大类和子类（如：直放站 > ZFZ系列）
2. 点击"添加字段"
3. 填写字段信息：
   - 字段名称：频率
   - 字段类型：spec（规格类型）⭐
   - 字段编码：F（用于MN号）
   - 是否必填：是
   - 用于产品编码：是
4. 为该字段添加选项：
   - 选项值：800MHz，编码：08
   - 选项值：900MHz，编码：09
   - 选项值：1800MHz，编码：18
5. 保存字段定义
6. 重复步骤2-5，添加其他规格（功率、驻波比等）

**数据写入**（复用现有表）：
```sql
-- 1. 添加规格字段定义
INSERT INTO product_code_fields
(subcategory_id, name, code, field_type, position, is_required, use_in_code)
VALUES (2, '频率', 'F', 'spec', 1, TRUE, TRUE);

-- 2. 添加字段选项
INSERT INTO product_code_field_options (field_id, value, code, position) VALUES
([字段ID], '800MHz', '08', 1),
([字段ID], '900MHz', '09', 2),
([字段ID], '1800MHz', '18', 3);
```

**说明**：
- ✅ 直接复用现有的 `product_code_fields` 和 `product_code_field_options` 表
- ✅ `field_type = 'spec'` 标识为规格类型字段
- ✅ 同时支持MN号编码和规格筛选功能
- ✅ 研发库和产品库共用同一套规格定义

---

### 流程2：产品添加（管理员）

#### 方式A：从研发库转化（自动）

**触发条件**：研发产品状态变为 "ready"（研发完成）

**操作流程**：
1. 进入研发产品详情页
2. 点击"转为正式产品"按钮
3. 系统自动：
   - 复制产品基础信息到 `products` 表
   - 复制规格信息到 `product_specs` 表
   - 设置 `source_type='dev_product'`
   - 设置 `source_dev_product_id`
4. 可选：将产品加入系列
5. 确认产品化

**数据写入**：
```sql
-- 1. 创建产品记录
INSERT INTO products (product_mn, product_name, category_id, subcategory_id, region_id,
                     retail_price, source_type, source_dev_product_id, productized_at)
SELECT mn_code, name, category_id, subcategory_id, region_id,
       retail_price, 'dev_product', id, CURRENT_TIMESTAMP
FROM dev_products WHERE id = 123;

-- 2. 复制规格（字段名保持一致）
INSERT INTO product_specs (product_id, field_name, field_value, field_code, display_order)
SELECT [新产品ID], field_name, field_value, field_code, ROW_NUMBER() OVER (ORDER BY id)
FROM dev_product_specs WHERE dev_product_id = 123;

-- 3. 更新研发产品状态
UPDATE dev_products SET status = 'productized', productized_product_id = [新产品ID]
WHERE id = 123;
```

**步骤3：系统查询匹配产品（后台自动）**

```sql
-- 用户选择：频率=不确定（默认800MHz），功率=50W

-- 查询符合默认规格的产品
SELECT p.*
FROM products p
WHERE p.series_id = 1
  -- 频率 = 800MHz（默认第一个值）
  AND EXISTS (
    SELECT 1 FROM product_specs ps1
    WHERE ps1.product_id = p.id
      AND ps1.spec_name = '频率'
      AND ps1.spec_value = '800MHz'
  )
  -- 功率 = 50W
  AND EXISTS (
    SELECT 1 FROM product_specs ps2
    WHERE ps2.product_id = p.id
      AND ps2.spec_name = '功率'
      AND ps2.spec_value = '50W'
  );

-- 结果：找到1个产品
-- id: 1, product_mn: 'DC-Z-08-50', product_name: '直放站800MHz 50W', retail_price: 5000
```

#### 任务3.2：服务层开发

**文件**：`app/services/product_configurator_service.py`（新增）

**主要功能**：
1. 获取系列的可变规格列表
2. 根据规格查询产品

4. 从研发库产品化

**示例**：
```python
# app/services/product_configurator_service.py
from app.models import Product, ProductSpec, ProductSeries, ProductRelation
from sqlalchemy import func

class ProductConfiguratorService:

    @staticmethod
    def get_series_variable_specs(series_id):
        """
        获取系列的可变规格（需要用户选择的规格）

        Returns:
            [
                {
                    'spec_name': '频率',
                    'values': ['800MHz', '900MHz', '1800MHz'],
                    'value_count': 3
                },
                ...
            ]
        """
        # 查询系列的所有产品
        product_ids = db.session.query(Product.id).filter_by(series_id=series_id).all()
        product_ids = [pid[0] for pid in product_ids]

        # 分析每个规格的唯一值数量
        results = db.session.query(
            ProductSpec.spec_name,
            func.count(func.distinct(ProductSpec.spec_value)).label('value_count'),
            func.group_concat(func.distinct(ProductSpec.spec_value)).label('values')
        ).filter(
            ProductSpec.product_id.in_(product_ids)
        ).group_by(
            ProductSpec.spec_name
        ).all()

        # 只返回有多个值的规格（需要选择）
        variable_specs = []
        for spec_name, value_count, values in results:
            if value_count > 1:
                variable_specs.append({
                    'spec_name': spec_name,
                    'value_count': value_count,
                    'values': values.split(',') if values else []
                })

        return variable_specs

    @staticmethod
    def find_products_by_specs(series_id, spec_filters):
        """
        根据规格筛选产品

        Args:
            series_id: 产品系列ID
            spec_filters: {
                '频率': '900MHz',
                '功率': '50W'
            }

        Returns:
            [Product, Product, ...]
        """
        query = Product.query.filter_by(series_id=series_id)

        # 为每个规格添加 EXISTS 子查询
        for spec_name, spec_value in spec_filters.items():
            query = query.filter(
                Product.specs.any(
                    (ProductSpec.spec_name == spec_name) &
                    (ProductSpec.spec_value == spec_value)
                )
            )

        return query.all()

    @staticmethod
    def get_series_related_products(series_id):
        """获取系列的关联产品"""
        relations = ProductRelation.query.filter_by(
            main_product_type='series',
            main_product_id=series_id,
            is_active=True
        ).order_by(ProductRelation.display_order).all()

        result = []
        for rel in relations:
            result.append({
                'relation_type': rel.relation_type,
                'display_name': rel.display_name,
                'product': rel.related_product,
                'default_quantity': rel.default_quantity
            })

        return result
```

### C. 常见问题FAQ

**Q1：老产品如何添加规格？**

A：两种方式：
1. 手动编辑产品，逐个添加规格
2. 准备Excel文件，使用批量导入工具

---

**Q2：规格名称必须统一吗？**

A：是的。建议在规格定义（spec_definitions）中预定义规格名称，确保一致性。例如统一使用"频率"而不是"频段"或"Frequency"。

---

**Q3：如果查询返回多个产品怎么办？**

A：配置器会显示所有符合条件的产品列表，用户可以选择其中一个。也可以提示用户选择更多规格来缩小范围。

---

**Q4：产品从研发库转化后，研发库的产品还能修改吗？**

A：可以查看，但建议锁定或标记为"已产品化"。如需修改，应该：
1. 修改产品库的产品
2. 或者在研发库创建新版本

---

**Q5：附加产品可以是必需的吗？**

A：可以。通过设置 `relation_type='required_accessory'`，配置器会自动勾选必需配件，用户无法取消。
