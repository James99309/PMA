## 🛠️ 修正方案

### 步骤1: 理解数据维度

**线上数据** (Quotation表)
- 来源：报价单（报价给客户的金额）
- 特征：未经折扣，这是初始报价金额
- 用途：交付给客户的报价
- 数据特性：可能有多个版本（多次修改）

**线下数据** (SettlementOrder表)
- 来源：结算单（给分销商的结算）
- 特征：已经过折扣，这是实际给付金额
- 用途：与分销商结算的金额
- 数据特性：基于批价单(PricingOrder)生成

### 步骤2: 数据提取SQL语句

**提取线上批价单**:
```sql
SELECT
    q.quotation_number as '批价单号',
    p.project_name as '项目名称',
    q.amount as '报价金额',
    q.created_at as '创建日期',
    q.updated_at as '修改日期',
    u.real_name as '销售员',
    q.project_stage as '项目阶段'
FROM quotations q
JOIN projects p ON q.project_id = p.id
JOIN users u ON q.owner_id = u.id
WHERE u.username = 'lihuawei'
  AND YEAR(q.created_at) = 2025
  AND q.is_deleted = false
ORDER BY q.created_at DESC;
```

**提取线下结算单**:
```sql
SELECT
    s.order_number as '结算单号',
    po.order_number as '关联批价单',
    p.project_name as '项目名称',
    s.total_amount as '结算金额',
    s.total_discount_rate as '折扣率',
    s.created_at as '创建日期',
    u.real_name as '销售员'
FROM settlement_orders s
JOIN pricing_orders po ON s.pricing_order_id = po.id
JOIN projects p ON s.project_id = p.id
JOIN users u ON po.created_by = u.id
WHERE u.username = 'lihuawei'
  AND YEAR(s.created_at) = 2025
ORDER BY s.created_at DESC;
```

### 步骤3: 去重复处理

#### 情况1: 完全一致的项目（应该保留一条）
- 项目测试1: 线上¥69,180 = 线下¥69,180
- 测试分支流程3: 线上¥16,780 = 线下¥16,780

**处理方式**: 保留线下结算单，删除线上报价单（因为结算单是最终执行的）

#### 情况2: 金额不一致的项目（需要业务确认）
- 张家浜楔形绿地: 线上¥336,735 vs 线下¥72,612（差¥264,123）
- 上海东方枢纽: 线上¥210,654 vs 线下¥172,070（差¥38,584）

**原因分析**: 可能是
- 报价金额与实际结算金额有差异
- 同一项目的多次修改
- 部分收货而非全部收货

**处理方式**:
1. 与销售部门确认差异原因
2. 如确实为同一批，使用结算金额（线下）作为绩效指标
3. 如为多批，需要拆分

#### 情况3: 仅线上有对应（无线下结算）
- 三亚太古里: 线上¥153,238，线下无对应
- 其他11个线上独有项目

**处理方式**:
- 检查是否还在流程中（未结算）
- 如已完成，需追踪为何无结算单
- 如流程中，暂不计入绩效

## 📌 关键决策点

### 决策1: 绩效指标使用哪个数据？

| 方案 | 数据来源 | 金额 | 优缺点 |
|------|---------|------|---------|
| **A. 使用线上报价** | Quotation表 | ¥2,771,195 | ✅ 保守估计; ❌ 可能含未执行项目 |
| **B. 使用线下结算** | SettlementOrder表 | ¥992,450 | ✅ 实际执行; ❌ 可能遗漏流程中项目 |
| **C. 使用两者平均** | 混合 | ¥1,881,823 | ❌ 不符合财务逻辑 |
| **D. 使用未结算** | 线上-线下 | ¥1,778,745 | ⚠️ 流程中订单，不应计绩效 |

**推荐**: **方案B** (使用线下结算金额¥992,450)
- 原因: 符合财务实际给付，避免流程中订单的不确定性

### 决策2: 如何处理重复项目？

**推荐流程**:
1. 自动去重: 删除线上,保留线下（因为线下是最终执行结果）
2. 手动审核: 逐个审核16个重复项目，确认是否真的重复
3. 业务确认: 让销售部门确认是否应该拆分计算（例如分期交付）

### 决策3: 流程中项目是否计绩效？

| 项目状态 | 线上 | 线下 | 计入绩效 | 原因 |
|---------|------|------|--------|------|
| 已完成结算 | ✓ | ✓ | ✅ 是 | 实际执行 |
| 流程中(待结算) | ✓ | ✗ | ❌ 否 | 不确定性大 |
| 已取消 | ✓ | ✗ | ❌ 否 | 未执行 |
| 部分结算 | ✓ | ✓ | ✓ 仅结算部分 | 按线下金额 |
