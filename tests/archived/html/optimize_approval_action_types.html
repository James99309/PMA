🔧 优化审批步骤执行动作选项

发现的问题和解决方案
❌ 发现的问题
1. 逻辑冲突

"分支决策"动作 vs "分支决策步骤"

  • 步骤类型: step_type = "branch"
  • 执行动作: action_type = "branch_decision"
  • ❌ 分支是步骤的类型，不应作为动作
2. 功能重复

"业务授权" vs "客服授权"

  • business_authorization
  • customer_service_authorization
  • ❌ 后端代码显示这是同一个功能
✅ 优化前选项
  • 授权编号
  • 报价审核
  • 支付处理
  • 项目授权
  • 渠道授权
  • 业务授权
  • 客服授权 (重复)
  • 分支决策 (冲突)
  • 批结算审批
🎯 优化后选项
  • 授权编号
  • 报价审核
  • 支付处理
  • 项目授权
  • 渠道授权
  • 业务授权 (包含客服功能)
  • 批结算审批
优化效果：
• 消除了逻辑冲突
• 减少了功能重复
• 简化了用户选择
🔍 问题分析详情
问题类型 具体问题 原因分析 解决方案
逻辑冲突 "分支决策"同时作为步骤类型和执行动作 概念混淆：分支是步骤的工作方式，不是审批通过后的处理动作 移除 branch_decision 选项
功能重复 "业务授权"和"客服授权"实现相同功能 后端 business_authorization() 内部调用 customer_service_authorization() 保留"业务授权"，移除"客服授权"选项
向后兼容 现有配置可能使用了被移除的选项 需要确保现有审批流程不受影响 在显示时将 customer_service_authorization 映射为"业务授权"

设计理念
🎯 概念清晰
  • 步骤类型 (step_type): 决定步骤的工作方式
  • 执行动作 (action_type): 决定审批通过后的系统处理
  • 两者职责分明，不应混淆
🔄 功能整合
  • 相同功能的选项进行合并
  • 减少用户选择的复杂性
  • 保持后端功能的完整性
📈 可维护性
  • 减少重复的模板映射代码
  • 简化选项管理和维护
  • 为将来的配置化改造做准备
兼容性处理

为了确保现有审批流程不受影响，我们采用了以下兼容性措施：

  • ✅ 显示映射: 已配置的 customer_service_authorization 在界面上显示为"业务授权"
  • ✅ 后端兼容: 后端处理逻辑保持不变，继续支持所有已配置的动作类型
  • ✅ 功能完整: 移除选项不影响任何实际业务功能
  • ⚠️ 新配置限制: 新创建的步骤只能选择优化后的动作选项
优化效果总结

通过清理执行动作选项，消除了概念冲突和功能重复， 让审批步骤配置更加清晰直观，便于用户理解和使用。

  • ✅ 逻辑清晰: 步骤类型和执行动作概念分离
  • ✅ 选项简化: 从9个选项优化为7个选项
  • ✅ 功能整合: 业务授权涵盖客服授权功能
  • ✅ 向后兼容: 现有配置继续正常工作
  • ✅ 代码简化: 减少了重复的映射逻辑
  • ✅ 用户体验: 更清晰的选项分类和说明
