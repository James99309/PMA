✅ 修复批价单项目类型字段"无可选值"问题

问题修复完成
问题根源分析

发现了字段值加载失败的根本原因：存在两个不同地方的处理逻辑冲突

🔍 问题详细分析
  • 通用处理 (第1141行)
    if field_name == 'project_type'
    只匹配直接字段名
  • 批价单处理 (第1196行)
    if field_name == 'project.project_type'
    只在批价单对象类型下生效
  • 冲突结果
    关联字段 'project.project_type' 无法匹配通用处理， 导致返回空数组，前端显示"无可选值"
🔧 修复方案
  • 扩展通用处理逻辑
    if field_name == 'project_type' or field_name == 'project.project_type'
    同时支持直接字段和关联字段
  • 移除重复处理
    删除批价单中重复的项目类型处理逻辑
    避免维护两套相同的逻辑
  • 保持兼容性
    继续支持项目和报价单的直接 project_type 字段
    不影响现有功能
📊 支持的字段场景
对象类型 字段名称 字段类型 处理方式 状态
项目 (project) project_type 直接字段 通用处理 ✅ 支持
报价单 (quotation) project_type 直接字段 通用处理 ✅ 支持
批价单 (pricing_order) project.project_type 关联字段 通用处理 ✅ 已修复
